## 회의록 발신자를 실제 사람과 연결하기

- **현재**: 회의록 검증은 "이 공개키를 가진 계정(이름 kyu)이 썼다"까지만 증명합니다. 계정 이름은 본인이 정한 값이라, 그 계정을 실제로 누가 쓰는지는 증명하지 못합니다.
- **방법**: 기관이 보증하는 명부를 원장에 둡니다.
  - 관리자가 사람을 확인한 뒤 "공개키 ↔ 실명/소속"을 원장에 등록합니다.
  - 체인코드는 관리자 Fabric 신원(`ctx.clientIdentity`)으로 온 등록만 받습니다.
  - 검증 스크립트는 명부를 읽어 "기관이 확인한 OOO의 키로 서명됨"까지 보여 줍니다.
- **먼저 필요한 것**: 지금은 API 서버가 모든 요청을 한 Fabric 계정(테스트 네트워크의 User1)으로 보냅니다. 관리자 신원을 분리하고 API 요청 인증(#20)을 먼저 해야 합니다.

## 보낸 메시지 수정

- **문제**: 보낸 메시지를 고칠 방법이 없습니다.
- **주의**: 저장된 메시지를 그대로 바꾸면, 그 메시지를 덮는 원장 기록이 모두 "불일치"가 되어 변조와 구분되지 않습니다.
- **방법**: 원본은 두고 "메시지 X를 이렇게 고침"이라는 수정 메시지를 새로 추가합니다.
  - 화면은 원본 자리에 마지막 수정 내용과 "수정됨" 표시를 보여 줍니다.
  - 수정 메시지도 보낸 사람의 공간에 서명되어 저장되므로, 원본을 쓴 사람만 고칠 수 있습니다.
  - 해시는 원본과 수정 메시지를 모두 포함하므로 예전 기록은 계속 "일치"하고, 수정 이력이 원장으로 증명됩니다.
  - 회의록 내보내기와 `verify-minutes`도 수정 메시지를 알아야 합니다.
