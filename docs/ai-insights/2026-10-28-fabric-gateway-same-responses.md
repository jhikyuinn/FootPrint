# API 서버 SDK 교체를 응답 비교로 확인 (#42)

- 지적/발견: `fabric-network`를 `@hyperledger/fabric-gateway`로 바꾸면 결과가 바이트 배열로 오고, 체인코드 에러 메시지가 에러의 `details`로 옮겨간다. 앱은 `/api/query`가 "없는 방"을 `None`으로 주는 동작에 기대고 있었다.
- 판단: 반영함. 결과를 디코딩하는 `parse`와 `details`까지 합치는 `errorText`를 두고, 기존 서버와 새 서버를 같은 원장에 붙여 응답을 비교했다.
- 이유: 조회 API 5종의 응답이 기존 서버와 바이트 단위로 같았고, 서명된 쓰기 요청 11가지 시험도 모두 통과했다. "같은 응답을 준다"는 이슈 완료 조건을 추측이 아니라 비교로 확인하려고 했다.
