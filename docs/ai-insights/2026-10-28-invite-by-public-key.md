# 초대를 아이디 대신 공개키로 저장 (#35)

- 지적/발견: 초대 API에 본인 확인을 붙이려 해도, 초대가 받는 사람의 아이디로 저장되어 있으면 API 서버는 "이 서명이 그 아이디의 주인 것인지"를 알 수 없다. API 서버는 GUN을 보지 않아 아이디와 공개키를 연결하지 못한다.
- 판단: 반영함. 초대를 받는 사람의 공개키(`ToPub`)로 저장하고, 조회와 응답은 그 키의 서명이 있을 때만 받는다.
- 이유: 서명이 어떤 공개키로 만든 것인지는 서버가 확인할 수 있으므로, 저장 기준을 공개키로 바꾸면 본인 확인이 가능해진다. 대신 아이디로 저장된 기존 초대는 보이지 않게 되는데, 시험 단계라 감수했다.
